## Часть 1: Подготовка и основы

#### Задача

Скрипт-обработчик логов с вложенными циклами и оптимизация их. 

#### Процесс работы

Логи генерируем произвольно. В каждый лог входит:

- id лога
- Дата и время лога
- Уровень важности сообщения
- Сообщение

Уровни важности сообщения:
- INFO
- WARNING
- ERROR
- DEBUG
- CRITICAL

Сообщение состоит из некоторого текста, который может включать:
- Логин пользователя
- IP
- Имя файла
- Время
- Процент

Имена всех пользователей храним в одном массиве.

Сформулируем задачу так: распределить все логи уровня ERROR по соответствующим пользователям. 

_1 вариант - Вложенные циклы:_

Проходимся по списку пользователей и для каждого пользователя проходимся по списку логов.

> Проблема: мы проходимся по списку логов столько раз, сколько у нас пользователей. Если логов 50 000, а категорий 5, мы сделаем **250 000 операций сравнения**.

_2 вариант - Оптимизация:_

Сразу проходимся по списку логов, уже потом выявляя пользователя.
> Количество операций сравнения снижается **экспоненциально**.

#### Структура подпроекта
- /1_log/generate_log.py - генерация 50 тысяч произвольных логов
- /1_log/main.py - реализация функции с вложенными циклами, оптимизированной функции и сравнение



#### Результаты

**Медленный способ:** 0.033072471618652344 сек\
**Быстрый способ:** 0.0035195350646972656 сек\
**Ускорение:** в 9.39682969787 раз

<h2 id="part2">Часть 2: Основы веба и API </h2>

#### Задача
Сервис для управления заметками.

#### Процесс работы
Сервер запустился на http://127.0.0.1:5000

Знакомимся с методами.
| **Метод** | Описание |
|-------|----------|
| **GET** | Получить заметки |
| **POST** | Создать заметку |
| **PUT** | Полностью обновить заметку |
| **DELETE** |  Удалить заметку |

Изучаем кода
| **Код** | Объяснение |
|-------|----------|
| **200** | Всё прошло успешно (GET, PUT, DELETE) |
| **201** | Успешно создано (POST) |
| **204** | Успешно, но возвращать нечего (DELETE) |
| **400** | Клиент прислал некорректные данные |
| **404** | Запрашиваемый ресурс не найден |
| **500** | Ошибка на сервере |

Каждому методу прописываем соответствующую функцию и путь.

```/notes/<int:note_id>``` - **user_id** передается прямо в адресе. 

В каждой функции проверяются данные, которые даются на вход (если имеются), в зависимости от метода изменяются данные и возвращается соответствующий код.

Быстрое изучение библиотеки **Flask**, в частности **request**, **jsonify**.

#### Структура подпроекта
- /2_api/main.py - реализация api (все методы) и тестовый словарь данных
- /2_api/note.json - данные для методов POST и PUT

#### Результаты

Задача выполнена: локальное **API** для заметок. 
Создание включало в себя изучение большого количества новой информации.

## Часть 3: Базы данных и работа с ними

#### Задача
Расширение **API**: работа с несколькими таблицами, фильтрация, пагинация.

#### Процесс работы

В **DBeaver** создаем базу данных **notes_db**. 
С помощью библиотеки **flask_sqlalchemy** созаем макеты таблиц **users**, **notes** и **comments** (последнюю впоследствии пришлось закомментировать ввиду отсутствия необходимости). 

**Users** включает колонны: 
- id
- имя 
- емайл

**Notes** включает колонны: 
- id
- id создателя
- заголовок
- текст
- дата создания 
- дата изменения

С помощью конструкции **relationship** устанавливаю связь между таблицами. Cоздание таблиц в основном файле. Если база данных пустая на момент запуска сервера, автоматически создаются 15 заметок и 5 пользователей для удобства тестирования.

Повторяю [Часть 2](#part2) для обеих таблиц: методы get, post, put, delete, возвращаемые коды и прочее. При этом работа со славарем меняется на работу с базой данных, которая требует дополнительные действия, например ``` db.session.commit()```.

Изменяю метод get у заметок. Добавляю фильтрацию по id пользователя:
```/notes?user_id=1```  - все заметки пользователя с id равным 1.
Добавляю пангинацию.
```/notes?page=1&per_page=5``` - в адресе прописываем номер страницы и количество записей на странице.
